# Sprint 05 — Testes, documentação e entrega

**Projeto:** Flappy Bird — Python e Pygame  
**Disciplina:** Programação para Engenharia Mecânica — UFS/DMEC  
**Aulas relacionadas:** 04.0 e 04.1  
**Etapa:** planejamento

## 1. Objetivo
Validar, documentar e preparar a entrega avaliativa e o repositório.

## 2. Pré-requisitos
Sprint 04 concluída e validada.

## 3. Tarefas de desenvolvimento
- [ ] Executar testes de regras que não dependam de interface gráfica
- [ ] Testar manualmente iniciar, jogar, pausar, perder, reiniciar e sair
- [ ] Revisar .gitignore, requirements.txt e instruções de instalação
- [ ] Produzir README com imagem do jogo e instruções para Windows
- [ ] Preparar relatório PDF e apresentação PowerPoint
- [ ] Conferir identificação e referências dos arquivos
- [ ] Revisar commits e publicar somente arquivos destinados aos alunos
- [ ] Testar download ZIP ou clone em ambiente limpo

## 4. Critérios de aceitação
- [ ] Jogo executa do início ao fim com instruções documentadas
- [ ] README contém imagem real do jogo e modo de execução
- [ ] Repositório não contém .venv, dados pessoais ou gabarito privado
- [ ] Relatório, apresentação e código-fonte estão prontos
- [ ] Créditos, referências e recursos externos estão identificados

## 5. Evidências de conclusão
- Link do repositório e captura do README
- Relatório PDF, slides e checklist de testes

## 6. Procedimento de validação
1. Execute o projeto com o ambiente virtual ativado.
2. Verifique cada critério de aceitação e registre o resultado.
3. Corrija falhas antes de iniciar a próxima sprint.
4. Registre as alterações no Git com mensagem descritiva.

## 7. Observações didáticas
- A avaliação é regida pela rubrica de 14 critérios da Aula 01.0; concluir sprints não substitui a apresentação.
